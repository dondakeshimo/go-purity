# 判定不能・判断が必要なケース

原理的に純粋性を判定できない（あるいは判定方針の判断が必要な）ケースを洗い出し、現時点の「推奨デフォルト」と「最終決定」を記録する。

> 凡例: ステータスは「未決定（要判断）」「既定（実装済み）」「保留」のいずれか。

## A. 参照透過性と参照型（定義そのものの曖昧さ）

| ID | ケース | 理由 | 推奨デフォルト |
|---|---|---|---|
| A.1 | ポインタ引数の先の読み取り `*p` | 参照先は呼び出し元と共有の可変メモリ | `ReadWeak` では許容、`ReadStrict` では不純。既定は `ReadWeak` |
| A.2 | スライス引数の要素読み取り | バッキング配列を共有 | 同上 |
| A.3 | マップ引数の参照・`Lookup` | 参照型 | 同上 |
| A.4 | インタフェース引数のメソッド呼び出し | 動的ディスパッチ＋内部状態 | CHA で解決。解決不能なら `UNKNOWN` |
| A.5 | 関数値・クロージャ引数の呼び出し | 呼び出し先が任意 | CHA で解決。解決不能なら `UNKNOWN` |
| A.6 | チャネルの受信/送信 | 同期・非決定 | 不純 |

## B. 制御フロー・停止性

| ID | ケース | 理由 | 推奨デフォルト |
|---|---|---|---|
| B.7 | 非停止（無限ループ・底なし再帰） | 副作用なしだが戻らない | 停止性は別問題とし、副作用がなければ `PURE` 扱い（要判断） |
| B.8 | `panic` / `recover` | 観測可能な効果 | `panic` は不純。同一関数内で `recover` され外部に漏れない場合の緩和は要判断 |
| B.9 | `defer` + `recover` | defer 先の純粋性次第 | defer 先を解析して合成 |
| B.10 | `go` 文 | 並行性・非決定 | 不純 |

## C. エイリアス/エスケープ解析の限界

| ID | ケース | 理由 | 推奨デフォルト |
|---|---|---|---|
| C.11 | エスケープ解析の精度限界 | 局所性を証明できない | 分類不能アドレスへの書き込みは `IMPURE`（`Provisional`） |
| C.12 | 再帰・相互再帰 | サイクル | 最小不動点で解決 |
| C.13 | 動的ディスパッチ解決不能 | CHA でも解決不能（reflect・外部型） | `UNKNOWN` |
| C.14 | 本体のない関数（アセンブリ・外部リンク） | SSA が生成されない | `UNKNOWN` |
| C.15 | `//go:linkname` 別実装 | 解析対象外の本体 | `UNKNOWN` |

## D. 言語・ランタイム機能

| ID | ケース | 理由 | 推奨デフォルト |
|---|---|---|---|
| D.16 | マップの `range` | 反復順序が実行毎に非決定 | 不純 |
| D.17 | 時刻・乱数（`time.Now`, `math/rand`） | 非決定 | denylist で不純 |
| D.18 | 環境・外部状態（`os.Getenv`, ファイル, ネットワーク） | 外部状態 | denylist で不純 |
| D.19 | 並行プリミティブ（`sync`, `sync/atomic`） | 並行 | denylist で不純 |
| D.20 | メモリ確保/GC | アロケーションは観測可能だが FP 慣習では副作用とみなさない | 確保は `PURE`（定義上の宣言） |
| D.21 | finalizer（`runtime.SetFinalizer`） | 観測可能 | denylist で不純 |
| D.22 | 浮動小数・`NaN` | `NaN != NaN` | 無視（一般慣習） |

## E. unsafe / reflect / cgo（方針確定済み）

| ID | ケース | 理由 | 既定 |
|---|---|---|---|
| E.23 | `unsafe` | 任意の型・メモリ操作 | 一律不純（`unsafe.Sizeof`/`Alignof`/`Offsetof` の純粋例外はオプション） |
| E.24 | `reflect` | 実行時リフレクション | 一律不純 |
| E.25 | `cgo` | C 呼び出し | 一律不純 |

## F. 未モデル化コード

| ID | ケース | 理由 | 推奨デフォルト |
|---|---|---|---|
| F.26 | 他パッケージ/標準ライブラリの未解析関数 | allowlist 外 | `UNKNOWN`（→ fail） |
| F.27 | コールバックとして渡される純粋関数 | 「関数の純粋性」と「呼び出し文脈」の分離が必要 | 関数本体を解析し、呼び出し元文脈は判定に影響させない |
| F.28 | メソッド値・束縛メソッド | レシーバが関数値に閉じ込められる | CHA/ルート分類で追跡 |

## G. パッケージ変数・init

| ID | ケース | 理由 | 推奨デフォルト |
|---|---|---|---|
| G.29 | パッケージレベル `var` 読み取り | 形式的には可変 | 不純（`const` のみ純粋）。初期化後不変 `var` の緩和は要判断 |
| G.30 | `init` 関数 | 読み込み時副作用の文脈 | 判定対象外 |
| G.31 | 他 goroutine からの変更（データ競合） | 解析対象外 | 純粋関数は呼び出し元状態を変えないため通常競合を起こさない |

## H. ジェネリクス

| ID | ケース | 理由 | 推奨デフォルト |
|---|---|---|---|
| H.32 | 型パラメータのメソッド呼び出し | インスタンス化依存 | 解決不能なら `UNKNOWN`、または各インスタンスを解析 |
| H.33 | 各インスタンス化の解析 | `Function.Origin`/`TypeArgs` で対応付け | インスタンス毎に判定 |
